# 每日洞察

**日期：** 2026-08-26

**核心：** Hermes 数据库自省日 — cron 反复遇到 schema 不熟悉导致的调试循环，暴露 fact_store 与 state.db 路径不清晰、session 表列名不一致（`created_at` vs `timestamp`）等问题，说明数据库文档/技能缺失。

**具体发现：**
1. `memory_store.db` 的 `facts` 表是长期记忆，Aug 26 无新写入（最后记录 5 月）
2. `state.db` 的 `sessions`/`messages` 表使用 `timestamp` 而非 `created_at`
3. `memory_banks` 表存在但结构解析异常
4. cron job 的"今日对话"实际来自 state.db 而非 fact_store

**教训：** fact_store 的定位需要明确——它是"主动沉淀的知识"还是"被动记录的操作历史"，当前 cron 每次都要重新摸索。建议将记忆分类固化到 skill 中，减少重复调试。
